# Тесты

Все тесты входят в репозиторий и запускаются автоматически (GitHub Actions, `.github/workflows/tests.yml`) на **Linux и Windows**.

## Запуск

```bash
npm install
npm test                 # типы + unit + integration + e2e
npm run test:unit
npm run test:integration
npm run test:e2e         # собирает приложение и запускает окно Electron (на Linux без экрана — через xvfb-run)
npm run package:win      # портативный архив для Windows в release/
npm run package:linux
```

Проверка типов: `npm run typecheck` (полная, нужны `@types/*` из npm), `npm run typecheck:core` (строго: ядро, хранилище, тесты), `npm run typecheck:offline` (интерфейс по упрощённым объявлениям — для сред без npm).

## Состав (этап 1)

### Unit — `tests/unit`

| Файл | Что проверяет |
|---|---|
| `core.test.ts` | Уникальность UUID; новый проект валиден; нормализация имени; ревизия растёт только при реальном изменении; обнаружение повторяющихся ID, висячих ссылок, неизвестных выводов, повторов позиционных обозначений, вывода в двух сетях, ошибок «вывод символа ↔ площадка», размещения с чужим корпусом; миграция v0 → v1 с сохранением ID; отказ на файле новее программы, на повторяющихся ID, на неверной структуре и лишних полях; переназначение UUID сохраняет все связи (символ–деталь–корпус–модель, сети, плата) и не трогает ссылки на каталог; проект и контрольные версии переназначаются одной таблицей; Undo/Redo с подписями и ограничением; версия совпадает с package.json |
| `elab.test.ts` | Круговой перенос `.elab` без потерь (документ, контрольные версии, вложения, связи); размер и SHA-256 каждого файла в манифесте; отказ на: не-ZIP, обрезанном файле, испорченных байтах (CRC), подмене содержимого (контрольная сумма), отсутствии манифеста, чужом формате, бэкапе вместо проекта, более новой версии формата, опасных путях `../` (zip-slip, в т.ч. подделанных прямо в заголовках ZIP), повторяющихся ID; миграция v0 внутри `.elab`; лишние файлы — предупреждение |
| `no-network.test.ts` | В `src/` нет сетевых API (`http`, `https`, `net`, `fetch`, `WebSocket`, URL) — гарантия офлайн-работы |
| `examples.test.ts` | Все примеры в `examples/` открываются и проходят проверки |

### Integration — эталонные задачи ngspice (`sim.test.ts`)

Настоящий ngspice (в CI обязателен: `ELAB_REQUIRE_NGSPICE=1`), сравнение с аналитикой в допуске: делитель 10 В на 10/10 кОм (5 В, 0,5 мА, знак тока источника), делитель 3:1, перегрузка резистора 0,36 Вт > 0,25 Вт, заряд RC τ = 1 мс (63,2 % при t = τ, 99,3 % при 5τ), старт из рабочей точки, перенапряжение конденсатора, отказ отправлять ошибочную схему, вырожденная схема (два источника параллельно), таймаут, отсутствие ngspice — честная ошибка.

### Integration — `tests/integration` (настоящая файловая система, отдельные процессы)

| Тест | Что проверяет |
|---|---|
| Жизненный цикл | Создать → изменить → сохранить → закрыть → открыть; переименование, дублирование (новые UUID, связи целы), удаление в корзину (файлы физически сохранены) |
| «Сохранить как» | Новый проект, исходный не тронут |
| Защита от записи мусора | Документ с повторяющимся ID не сохраняется, файл на диске не меняется |
| Версии | `.bak` предыдущего сохранения; хранится 20 автоматических контрольных версий, ручные — все |
| Повреждённый проект | Виден в списке с ошибкой, а не исчезает |
| Очередь записи | 30 параллельных автосохранений/сохранений не портят файлы |
| Авария (SIGKILL) | Дочерний процесс автосохраняет и убивает себя; при запуске сбой обнаружен, сохранённая версия цела, рабочая копия восстанавливается |
| Убийство во время записи | 6 раз убиваем процесс в случайный момент непрерывной записи — ни одного повреждённого файла |
| Перенос между ПК | Две независимые папки данных: экспорт → импорт на чистом «ПК 2» (ID сохранены, связи целы, контрольные версии перенесены) → правка → обратно на «ПК 1»: конфликт → «как копию» / «заменить» (старый — в корзину) |
| Вложения | Переносятся с проверкой SHA-256 |
| Полный бэкап | Восстановление на чистом ПК: все проекты, несохранённые рабочие копии, личный каталог, журнал; продолжение работы |
| Отмена восстановления | Автокопия перед восстановлением создаётся и сама восстанавливается |
| Повреждённый бэкап | Отклоняется до каких-либо изменений; файл проекта вместо бэкапа — понятная ошибка |
| Прерванное восстановление | Сбой в момент замены папок исправляется при следующем запуске |
| Блокировка | Вторая копия программы на той же папке данных не запускается |
| Кириллица в путях | Папка данных `…\Мои документы\Электронная лаборатория\data`: сохранение, экспорт, бэкап и восстановление в `…\Флешка\Резерв` |
| `package-win.test.ts` | Портативный Windows-архив: состав, контрольная сумма, `.exe` идентичен официальному Electron, нет карт исходников и сетевых ссылок |

### E2E — `tests/e2e` (настоящее окно Electron, Playwright)

| Сценарий | Что делает пользователь |
|---|---|
| Жизненный цикл | Создаёт проект, ставит заметки, Ctrl+Z / Ctrl+Y / кнопки, Ctrl+S, закрывает окно, запускает снова, открывает, переименовывает, дублирует, удаляет |
| Авария | Правка → «автосохранено» → процесс убит → запуск: сообщение об аварийном завершении, отметка в списке, «Восстановить» → правка на месте |
| Закрытие | Крестик с несохранёнными изменениями: «Сохранить» — сохранено; «Не сохранять» — отброшено, без ложного предложения восстановления |
| Контрольные версии | Создать с подписью → изменить → «Вернуть» → Ctrl+Z отменяет возврат |
| Перенос | ПК 1: экспорт `.elab` и полный бэкап «на флешку» (системные диалоги подменяются) → ПК 2: импорт, правка, повторный импорт → конфликт → копия → ПК 3: восстановление бэкапа, правка |
| Повреждённые файлы | Обрывок архива и бэкап вместо проекта — понятные сообщения, данные не меняются |
| Сквозной прототип (`prototype.spec.ts`) | Схема делителя через интерфейс → расчёт ngspice → щупы: 2,5 В, смена щупов местами −2,5 В без пересчёта → новый номинал: старое показание не выводится, после перезапуска 1,599 В → удаление земли: расчёт не выполняется, причина названа → плата: синхронизация, расстановка, запрет дорожки между разными цепями, три дорожки, DRC чист → SVG 1:1 → `.elab` → другой ПК: связи, щупы и дорожки на месте, тот же расчёт |
| Портативный режим | Запуск собранного пакета: данные в `data` рядом с программой; папка целиком перенесена в «другой ПК\Электронная лаборатория» (кириллица и пробелы) — проект открывается |

E2E выполняются на экранах разного размера (проверено локально на 800×600, 1024×768, 1400×900; в CI на Windows экран раннера маленький).

### Пробный запуск — `scripts/ci/run-portable.mjs` (CI, Windows)

Прямой запуск `ElectronLab.exe` без Playwright: из папки сборки и из копии в папке с кириллицей; проверяется, что окно показано и папка `data` создана рядом с программой. Диагностика запуска (`ELAB_DEBUG=1`) выводится аннотациями GitHub.

## Что автотесты не покрывают

- Запуск на ПК пользователя с флешкой — чек-лист в [ADR-0001](adr/0001-desktop-shell-and-portability.md). Все наборы, включая e2e и портативный `.exe`, проходят в CI на `windows-latest` (Windows Server), но это не ваш компьютер.
- Внешний вид — проверяется глазами по скриншотам в отчёте этапа.
