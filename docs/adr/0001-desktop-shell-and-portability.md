# ADR-0001. Оболочка приложения, офлайн-работа и портативность

- Статус: **принято** (для этапа 1); проверка запуска на ПК пользователя — по чек-листу в конце, до приёмки этапа 1.
- Дата: 10.10.2026
- Целевая платформа: Windows 10/11 x64 (основной и второй ПК для проверки переноса).

## Контекст

ТЗ требует: браузерный интерфейс (React + TypeScript), полноценную работу без интернета после установки, перенос проектов и всего каталога на другой ПК через флешку, портативную сборку, локальный запуск ngspice. Обычная ссылка GitHub Pages не гарантирует офлайн-работу.

Рассмотренные варианты:

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Electron** | Chromium + Node.js в одном пакете; один и тот же код хранилища работает в приложении и в автотестах на Node; простой запуск ngspice дочерним процессом; портативная сборка для Windows собирается из официального архива без компилятора; e2e-тесты через Playwright | Размер ~370 МБ распакованно (~145 МБ в zip) |
| Tauri | Маленький размер | Сборка под Windows требует Rust-тулчейна MSVC или кросс-компиляции; системный WebView2 на чистом ПК может отсутствовать/различаться версией; файловая логика на Rust — второй язык и отдельные тесты |
| Локальный Node-сервер + системный браузер | Нет «тяжёлой» оболочки | Нужен переносной node.exe, порт, браузер пользователя (версия/расширения/политики не под контролем), закрытие вкладки ≠ закрытие программы, сложнее предупредить о несохранённых изменениях |

## Решение

1. **Electron 43.6.0** (официальный архив `electron-v43.6.0-win32-x64.zip`, SHA-256 сверяется со `SHASUMS256.txt` релиза при сборке).
2. Интерфейс — React 19 + TypeScript, собирается esbuild в статические файлы внутри приложения. Никаких загрузок из сети во время работы: Content-Security-Policy `default-src 'self'`, навигация и открытие новых окон запрещены.
3. Вся работа с диском — только в главном процессе (`src/storage`, чистый Node.js). Интерфейс общается с ним через узкий IPC-мост (`window.elab`), `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`.
4. **Портативность.** Если рядом с исполняемым файлом лежит `portable.flag`, все данные (проекты, каталог, настройки, журнал, резервные копии) хранятся в папке `data\` рядом с программой — т.е. на той же флешке. Без флага — в профиле пользователя Windows (`%APPDATA%\ElectronLab\data`). Поставляется портативный zip; установщик (NSIS) — позже, отдельной задачей.
5. **ngspice (этап 4).** Основной путь — официальная консольная сборка ngspice для Windows, кладётся в `resources\ngspice\` и запускается дочерним процессом в пакетном режиме (`ngspice_con -b`), с таймаутом и разбором вывода. Резервный путь — WebAssembly-сборка ngspice, если она пройдёт те же эталонные тесты. Окончательный выбор фиксируется в ADR-0002 до начала этапа 4 после пробного запуска на ПК пользователя. На этапе 1 симулятор не подключается и в интерфейсе явно помечен как «не реализовано».
6. Зависимости времени выполнения сведены к минимуму: `react`, `react-dom`, `jszip` (ZIP-контейнер), `zod` (валидация). Всё упаковывается внутрь приложения.

## Последствия

- Размер портативной сборки около 145 МБ в zip (~370 МБ распакованно) — приемлемо для флешки.
- Иконка и сведения о версии в `.exe` пока стандартные от Electron (для их замены нужен rcedit под Windows); на работу не влияет.
- **Найдено в CI на Windows (`windows-latest`):**
  - Блокировка единственного экземпляра Electron (`requestSingleInstanceLock`) в тестах не бралась, и программа молча закрывалась. Отдельный эксперимент показал, что кириллица в пути профиля ни при чём; вероятная причина — оставшиеся процессы Electron от предыдущих запусков. Решение: отказ этой блокировки больше не закрывает программу; от двух копий на одной папке данных защищает собственная блокировка хранилища (`session.lock`, проверена тестами). Служебная папка Electron названа латиницей (`ElectronLab`).
  - `fs.cpSync` в Node.js 22 на Windows искажает кириллические имена путей. Программа его не использует; в скриптах сборки и тестах заменён собственным `copyDir`.
  - Окно открывается по размеру рабочей области экрана, боковые панели сжимаются (экраны 1024×768 и меньше).
  - Портативный `ElectronLab.exe` запускается из папки сборки и из папки с кириллицей и пробелами в пути; данные создаются в `data` рядом с программой.
- Код хранилища тестируется напрямую на Node без запуска окна; сквозные сценарии — Playwright + Electron.
- В среде разработки, где делался этап 1, нет Windows: портативная сборка для Windows собрана и проверена на структуру и контрольные суммы, а такой же портативный режим проверен e2e-тестами на Linux-сборке Electron той же версии. **Запуск на реальном Windows-ПК выполняет пользователь по чек-листу ниже.**

## Чек-лист проверки на целевых ПК (Windows 10/11)

1. Распаковать `ElectronLab-<версия>-win-x64-portable.zip` на флешку. Отключить интернет.
2. Запустить `ElectronLab.exe`. Ожидается: окно «Электронная лаборатория», в строке состояния «Портативный режим, данные: <путь к флешке>\data».
3. Создать проект, добавить 2–3 заметки, «Сохранить», закрыть, открыть снова — заметки на месте.
4. Добавить заметку, подождать «Автосохранено», завершить процесс через Диспетчер задач. Запустить снова — должно появиться предложение восстановить изменения.
5. «Экспорт проекта» на флешку, «Резервная копия всего» на флешку.
6. На втором ПК без интернета: запустить ту же портативную сборку с флешки (или скопированную на диск), «Импорт проекта» / «Восстановить резервную копию», продолжить редактирование.
7. Сообщить результат; при ошибке — текст сообщения и файл `data\journal.jsonl`.
