# ADR-0002. Подключение ngspice

- Статус: **принято** (этап 1b — сквозной прототип)
- Дата: 10.10.2026

## Контекст

ТЗ требует проверенный SPICE-движок, работу без интернета и честные сообщения о невозможности расчёта. ADR-0001 наметил два пути: родной ngspice отдельным процессом или WebAssembly-сборка.

Проверено на этапе 1b:

| Вариант | Результат проверки |
|---|---|
| WebAssembly (EEcircuit-engine) | В репозитории нет готовой сборки, нужен Emscripten; npm-пакет из среды разработки недоступен. Отложено. |
| ngspice из исходников | ngspice-47 (зеркало официального репозитория SourceForge на GitHub, тег `ngspice-47`) собран с XSPICE и решателем KLU; эталонные задачи проходят. |
| Официальная Windows-сборка ngspice | Скачивается в CI с SourceForge и кладётся в портативный пакет (см. ниже). |

## Решение

1. **Движок:** ngspice-47, консольный режим `ngspice -b circuit.cir` (в Windows — `ngspice_con.exe`), отдельный процесс на каждый расчёт.
2. **Обмен данными:** netlist пишется во временную папку; результаты — ASCII raw-файлы `op.raw`, `tran.raw` (`set filetype=ascii`, `write`). Имена файлов относительные, процесс запускается с рабочей папкой = временной: кириллица в пути профиля не попадает в аргументы ngspice.
3. **Защита:** таймаут 30 с (процесс убивается), ограничение объёма вывода, папка удаляется после расчёта.
4. **Проверки до ngspice** (`src/sim/netlist.ts`): пустая схема, нет земли, неподключённый вывод, висящий узел, узел без пути постоянного тока к земле, закороченный источник, нет модели, нет или недопустимый номинал. Схема с такими ошибками в ngspice не отправляется.
5. **Ошибки ngspice** классифицируются (вырожденная матрица, сходимость, отказ netlist, нет результата, таймаут) и показываются по-русски; исходный вывод ngspice сохраняется в подробностях.
6. **Числа** передаются без SI-суффиксов (в SPICE «M» — милли, а не мега).
7. **Поиск исполняемого файла:** `ELAB_NGSPICE` → `resources/ngspice/bin` портативной сборки → `vendor/ngspice/<платформа>/bin` (разработка) → `PATH`. Если не найден — расчёт честно не выполняется.
8. **Знаки токов:** ток R/C — от вывода 1 к выводу 2; ток источника — как в ngspice (через источник от «+» к «−», отрицательный при отдаче мощности).
9. **Переходный процесс** по умолчанию — «включение питания при t = 0» (`uic`, конденсаторы разряжены); можно отключить и стартовать из рабочей точки.

## Поставка

- **Windows:** официальный архив `ngspice-47_64.7z` (13,8 МБ) скачивается в CI с SourceForge (`scripts/fetch-ngspice.mjs`); SHA-256 `59225971…518f5a` закреплена в `scripts/ngspice-win.json` после первой загрузки и сверяется при каждой сборке — подмена архива ломает сборку. Содержимое `Spice64` кладётся в `resources/ngspice`, источник, сумма и лицензия (модифицированная BSD) — в `resources/ngspice/SOURCE.txt`.
- **Проверено в CI на `windows-latest`:** эталонные задачи и сквозной e2e-прототип проходят на этой сборке ngspice.
- **Linux (разработка, CI):** сборка из исходников ngspice-47 в `vendor/ngspice/linux-x64` (в git не хранится) или системный пакет `ngspice` в CI.

## Последствия

- Каждый расчёт — новый процесс (~10 мс на запуск для простых схем) — приемлемо для интерактивной работы.
- Версии на Linux-CI (системный пакет) и Windows (47) могут различаться; эталонные тесты сравнивают с аналитикой в допуске, а не с «золотыми» числами конкретной версии.
- В среде разработки ngspice собран из зеркала на GitHub, а не с SourceForge (недоступен). Windows-пакет берётся с официального SourceForge в CI.
- Цифровая логика, микроконтроллеры и ИС без SPICE-моделей не моделируются — будет показано «нет модели».
