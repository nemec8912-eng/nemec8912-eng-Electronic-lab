# ADR-0003. Каталог деталей и импорт из библиотек KiCad

- Статус: **принято** (этап 2)
- Дата: 11.10.2026

## Контекст

ТЗ (раздел 2) требует каталог реальных компонентов с карточками, редактор микросхем (выводы, типы, функции), корпуса разных семейств с шагом, ключом и нумерацией, несколько корпусов на один партномер с явным соответствием «вывод символа ↔ площадка», проверки дубликатов и пиновки, импорт из интернета с указанием источника и лицензии, который пользователь подтверждает, и офлайн-работу после импорта. SPICE-модель хранится отдельно; описание выводов модель не создаёт.

## Решение

1. **Комплект детали** (`PartBundle`): деталь + символ + корпуса + модель (или `null`). Это единица хранения в каталоге и переноса в проект. При размещении на схеме комплект **копируется** в библиотеку проекта с новыми UUID (`embedBundle`), связь с каталогом — `origin.catalogPartId`. Проект самодостаточен: правка каталога проект молча не меняет.
2. **Два каталога:**
   - встроенный справочник (`src/catalog/builtin.ts`) — в коде, только чтение, детерминированные UUID (`stableId`), все реальные детали помечены «не сверено», у полупроводников и микросхем модели нет;
   - личный каталог — `data/library/catalog.json` (`schemaVersion` каталога 2, миграция с 1), атомарная запись, копия `.bak`, проверка целостности перед записью, повреждённый файл не перезаписывается. Входит в полный бэкап.
3. **Формат проекта v3** (миграция v2 → v3): сведения о детали (назначение, маркировка, номинал, допуск, пределы, температура, полярность, даташит, источник, лицензия, «сверено» с датой), функции выводов, монтаж/шаг/нумерация/генератор корпуса. Та же миграция поднимает старый личный каталог.
4. **Корпуса** строятся генераторами семейств (DIP, SOIC, SOP, TSSOP, QFP, QFN, BGA, SOT-23, SOT-223, TO-92, TO-220, аксиальный, радиальный, чип, SMA/SMB/SMC, штыревой, клеммник) с типовыми размерами площадок; интерфейс прямо говорит, что их нужно сверить с даташитом. Ключ первого вывода: квадратная площадка 1 у выводных, метка и текст «ключ» у всех.
5. **Соответствие «вывод ↔ площадка» никогда не меняется молча.** При добавлении корпуса предлагается сопоставление по совпадающим номерам; удаление вывода убирает только его строки; смена категории у детали с корпусами не заменяет обозначение (иначе номера выводов поменяли бы смысл). Ошибки соответствия (вывод без площадки, площадка у двух выводов, несуществующая площадка, повтор номеров) не дают сохранить деталь; лишние площадки — предупреждение.
6. **Импорт — из официальных библиотек KiCad**, а не «по партномеру из интернета вообще»: это единственный открытый источник символов и посадочных мест с понятной лицензией и машиночитаемым форматом. Варианты:
   - официальные библиотеки на gitlab.com (`kicad-symbols`, `kicad-footprints`, ветка `master`); поддерживаются единый файл `.kicad_sym` (KiCad 6–8) и библиотека-папка `.kicad_symdir` KiCad 9 (символ и его родитель — в разных файлах, список — через API GitLab);
   - файлы `.kicad_sym` / `.kicad_mod` с компьютера (например, из установленного KiCad) — полностью офлайн.
7. **Порядок импорта:** выбор библиотеки и символа → посадочные места (подставляются из свойства символа Footprint) → предпросмотр: обозначение, корпуса, таблица выводов по каждому корпусу, источник (адреса файлов), лицензия, список упрощений → «Проверить и сохранить…» открывает редактор → сохранение только после действия пользователя. Деталь помечается «не сверено», модель для расчёта не создаётся (кроме идеальных R, C, L).
8. **Перевод из KiCad:** категория и префикс по ГОСТ 2.710 — по позиционному обозначению KiCad, имени и библиотеке; стандартное обозначение (диод, транзистор, MOSFET…) перенумеровывается по именам выводов KiCad (у BC547 в KiCad 1 = C, 2 = B, 3 = E), иначе — прямоугольник по выводам; «земля» узнаётся по имени (в KiCad она тоже `power_in`); инверсия `~{RST}` — черта сверху; многосекционные символы собираются в один прямоугольник; площадки с повторяющимися номерами и сложной формы упрощаются с предупреждением.
9. **Лицензия:** данные библиотек KiCad — CC-BY-SA 4.0 с исключением: проекты и файлы для производства, созданные с ними, под лицензию не подпадают. Это записывается в `origin.license` каждой импортированной детали. У файлов с компьютера лицензия неизвестна — так и пишется.

## Сеть

Обращение к сети есть только в `src/catalog-import/source.ts` и только к `https://gitlab.com` (проверка адреса перед запросом), по нажатию «Загрузить из интернета» / «Показать деталь». Таймаут 60 с, предел размера 60 МБ, имена библиотек и посадочных мест проверяются (без `..`, `/`). Автотест `no-network.test.ts` проверяет, что остальной код сетевых API не содержит. Окно программы по-прежнему не может загружать внешние адреса (CSP и фильтр запросов); ссылка на даташит открывается в браузере системы только по нажатию и после подтверждения.

## Проверка

- Unit: разбор S-выражений, символов (наследование, секции, скрытые выводы, KiCad 6–9), посадочных мест (KiCad 7–8 и старый формат `module`), перевод в деталь — на фикстурах `tests/fixtures/kicad` (набраны вручную по образцу официальных файлов).
- Integration: источник в режиме тестовых данных (`ELAB_KICAD_FIXTURE_DIR`), включая библиотеку-папку.
- E2E: импорт через интерфейс — «официальная» библиотека (фикстуры вместо gitlab.com), библиотека-папка, файлы с компьютера.
- CI (Linux): `scripts/kicad-live.mts` — импорт настоящих NE555P + DIP-8 + SOIC-8, BC547 + TO-92 и резистора из Device с gitlab.com; распиновка NE555P сверяется с даташитом (1 GND, 2 TRIG, 3 OUT, 4 RST, 5 CONT, 6 THRES, 7 DISCH, 8 VCC). Шаг не роняет сборку при недоступности сайта, результат — в аннотациях.

## Отвергнуто

- Произвольные сайты производителей и агрегаторы (Octopart и т. п.): требуют ключей/учётных записей, лицензии на данные неоднозначны, форматы закрыты.
- Автоматическое создание SPICE-модели по описанию выводов — противоречит ТЗ.
- Хранение ссылки на деталь каталога вместо копии в проекте — ломает перенос проекта на другой ПК.
