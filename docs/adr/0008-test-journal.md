# ADR-0008. Журнал испытаний, сравнение с расчётом, ревизии и откат

- Статус: **принято** (этап 7)
- Дата: 12.10.2026

## Контекст

ТЗ (раздел 9):
- Журнал испытаний на каждую версию проекта. В записи — дата, ревизия схемы и платы, фактические измерения в узлах, приборы, напряжение питания, условия, фото и примечания, заменённые и сгоревшие компоненты, обстоятельства неисправности.
- Сравнение измерений с расчётом с учётом допусков; расхождения и гипотезы причин — без выдуманных диагнозов.
- Изменение характеристик, модели, схемы и разводки — с историей и откатом.
- Глобальная библиотека не переписывается по одному наблюдению: изменения локальны для проекта, перенос в каталог — с подтверждением.
- Проверки: отказ резистора или транзистора, новый номинал, пересчёт, синхронизация платы, сравнение ревизий, возврат старой.

В формате с v1 уже было поле `tests` (простые записи), были контрольные версии и вложения.

## Решение

1. **Запись привязана к ревизии.** При создании записи сохраняется снимок проекта — контрольная версия вида `test`. Такие снимки не удаляются автоматически, переносятся в `.elab` и копируются вместе с проектом. С этим снимком считается расчёт, его сравнивают с текущей ревизией и восстанавливают. Записи из старой версии программы снимка не имеют — для них расчёт и сравнение идут по текущей схеме, и это сказано.
2. **Точка измерения:**
   - узел — напряжение относительно земли схемы;
   - деталь — напряжение между выводами 1 и 2, ток через деталь или ток вывода, сопротивление выпаянной детали;
   - точка, описанная словами, — с расчётом не сравнивается.

   Подпись точки хранится на момент записи, поэтому запись читается, даже если деталь потом удалили.
3. **Расчётное значение** — рабочая точка ngspice для снимка ревизии, при измеренном питании, если оно указано и источник на схеме один. Разброс — наихудший случай в линейном приближении: каждое сопротивление с допуском ставится на ±допуск, отклонения складываются (не больше 20 деталей). Ёмкости и индуктивности в рабочей точке не влияют, допуски источников и разброс полупроводников не учитываются — это написано в описании метода у каждого значения. Сопротивление детали сравнивается с номиналом и допуском без расчёта схемы. Если величина в расчёте не определена, значения нет и названа причина.
4. **Совпадение:** |измерено − расчёт| ≤ разброс + погрешность прибора (по умолчанию ±(1 % + 0,01 В) для напряжения, ±(1,5 % + 1 мА) для тока, ±(1 % + 0,1 Ом) для сопротивления; правится у каждого измерения).
5. **Гипотезы** строятся только при расхождении и только из фактов: соотношение «измерено / расчёт / питание», детали, подключённые к точке, отметки «сгорела / неисправна / заменена» в этой записи, непроверенные модели, разница между измеренным и схемным питанием. Подаются как «что проверить», с пометкой «не диагноз».
6. **История и откат.** Правки номиналов, моделей, схемы и платы — обычные правки с Undo/Redo и контрольными версиями. Сравнение ревизий (`diffDocs`) — по UUID и составу цепей, а не по координатам. **Возврат ревизии не стирает журнал:** из снимка берутся схема, детали, плата и настройки, а журнал испытаний, вложения и журнал изменений остаются текущими. Это относится ко всем контрольным версиям — иначе возврат уничтожил бы записи об испытаниях, сделанных после снимка.
7. **Каталог.** Изменения детали в проекте не трогают «Мой каталог». «Добавить в мой каталог» спрашивает подтверждение. Если деталь там уже есть, сохраняется новая деталь, а существующая не меняется.
8. **Фото** копируются в папку проекта (`attachments/<id>/<имя>`) с контрольной суммой. Принимаются только изображения не больше 25 МБ. Фото входят в `.elab` и полный бэкап, при чтении повреждение обнаруживается.

## Проверка

- Unit: миграция v6 → v7, правила совпадения с числами, номинал и допуск, гипотезы, записи и фото, возврат без потери журнала, переназначение ссылки на снимок при копировании, сравнение ревизий.
- Integration (ngspice): разброс делителя 10 к / 4,7 к при 1 % совпадает с формулой наихудшего случая до 1e-9, подстановка измеренного питания, отказ выдумывать значение. Хранилище: фото и снимки переживают экспорт, импорт копией и дублирование.
- E2E: полный сценарий ТЗ через интерфейс плюс перенос на другой ПК.
